# ALR-TW 1.0.0

1.0 定義可維護的研究、來源驗證及答案驗證介面；支援範圍見 [1.x 契約](V1_CONTRACT.md)。
本專案不包含 LLM、代理實作、正式法律資料庫或部署者的私人資料。

## 安裝與操作

從本專案 GitHub Release 下載正式 wheel，在獨立 Python 環境安裝：

```sh
python -m pip install './alr_tw-1.0.0-py3-none-any.whl[live]'
alr-tw doctor
alr-tw --help
```

Python 最低 3.11。受管研究儲存需要 POSIX 安全檔案操作；Windows 不在支援範圍。
基本安裝可執行合成示範；官方網路功能需要 `live`，TLR 候選功能需要 `tlr`。
設定與 MCP 接線見 [部署起點](DEPLOYMENT_STARTING_POINTS.md) 及 [客戶端指南](AGENT_CLIENT_GUIDE.md)。
使用 `ALR_TW_STORAGE_PATH` 指定專用本機儲存，升級前停止寫入並完整備份。

## 研究與草稿

研究建立、接續、計畫、狀態與來源查證由伺服器掌控；15 個正式 MCP 入口見契約。
研究預算預設 120 秒、50 次 HTTP 嘗試，跨操作與重啟持續保存。
用盡預算保留材料與未完成義務；不能換操作編號重設預算。
法規搜尋詞與裁判搜尋詞分開，保留原問題；日期歧義需澄清，不自動改寫法律適用時點。
增訂條號保留「第 N 條之 M」完整識別；法名簡稱必須由官方目錄解析。

`review-draft`／`review_legal_draft` 提供唯讀內部草稿與引用位置提案。
先核對 `draft_sha256`，只將 `proposed`／`unchanged` 的位置套到對應主張。
改稿後重新預檢，以新的操作編號呼叫 `validate-draft` 或 `complete-research`。
位置提案、研究完成、`ready_for_draft` 都不授權展示答案。
只有嚴格驗證回傳 `safe_to_present=true` 的正式答案可呈現，並須保留所有限制。

裁判名稱等價需同法院、年度、字別、案號、唯一文書識別及內容雜湊；
法院名稱臺／台、年／年度可正規化，分院與判決／裁定矛盾不能省略。
單一相鄰純引用句僅接受「完整已綁定主張。參見（合格引用）。」等有界格式；
不可跨段、跳過主張、夾帶結論或用引用掩蓋未支持文字。

## 可選提供者與資料包

HMAC 本機資料包需外部可信金鑰、完整映像雜湊、期限及結構驗證；不是司法簽章。
`build-pack`、`inspect-pack`、`import-pack` 用法見命令列說明與 [官方提供者](OFFICIAL_PROVIDERS.md)。
資料包搜尋仍是候選；精確回查符合條件才可成為證據。本機包不自行網路回退。
有限歷史法規、函釋、遠端精確包與語意顧問須明示啟用；不承諾全域覆蓋。
複合提供者的官方回退核對來源與證據身分；重新查證建立獨立不可變快照。
