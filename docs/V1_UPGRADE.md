# 升級到 1.0.0

公開升級基線為 0.12.0。停止舊寫入程序並完整備份資料目錄、設定與外部金鑰，
再於獨立環境安裝 1.0.0 wheel。不要讓新舊程序同時寫入同一目錄。

1. 執行 `doctor`、MCP 初始化與工具發現，核對既有研究狀態及原期限。
2. 以新操作編號重新驗證有效研究；需要新材料時建立新研究。
3. 過期或無法接續時明示停止；經使用者選定範圍清除後重建，不延長證據期限。

| 項目 | 0.12.0 → 1.0.0 |
|---|---|
| 工具 | 保留原工具，新增研究完成、唯讀預檢及指引 |
| 主張覆蓋 | 完整子句含短結論均須綁定；不保留舊錯誤放行 |
| 舊重播 | 無 request_digest 回 OPERATION_REQUEST_MISMATCH；新操作編號重驗 |
| 儲存 | 增補操作摘要及接續欄位，原結果及期限保持 |
| 清除 | 升級不能復活已清除研究；完整清除後建立新實例 |
| 回應 | 新增指引、查詢準備及受限結果；封閉型客戶端需更新解析 |
| 設定 | 原模式、profile、TTL 保留；新可選提供者預設不啟用 |

研究新增伺服器擁有的 `budget` 欄位，舊記錄缺欄位時依預設讀取。
首次推進或綁定研究的查證啟動期限，包含呼叫間等待；重播不重算預算。
預設 120 秒、50 次 HTTP 嘗試。耗盡保留未完成義務與材料，不延長原來源期限。
舊版不保證可讀取新版寫入的記錄。回退必須停止新程序，恢復升級前獨立備份與舊套件；
不可刪除新欄位假裝相容，回退也不能恢復已刪除而沒有備份的資料。

`scripts/smoke_upgrade.py` 用真正隔離安裝的舊、新 wheel，核對原材料、期限、
重播、重新驗證、到期及清除。舊 fixture 只提供合成資料，儲存由舊套件寫入。
CI 基線固定於公開提交 `95bd9e848699228298a5ec7e4d5308515514472e`；
不宣稱重新建置的舊 wheel 與當年發布位元組相同，也不代表所有歷史資料皆已驗證。
